# Агроном Онлайн 1.3.1 (15)

Пакет `ua.agronom.online`, продукт `agronom_premium_monthly`. Предыдущая опубликованная версия: 1.2.4 (14). Сборка подписывается существующим upload-ключом; OAuth, пакет и Firebase-проект не менялись.

## Совместимость аккаунтов

Восстановлена архитектура опубликованного приложения: Firebase Authentication и Firestore проекта `agronomonline-68820`. Google и email/password используют тот же Firebase UID; документы `users/{uid}` обновляются с сохранением существующих полей. Клиент не изменяет `isPremium` существующего профиля. Сессия старого Render Auth не считается Firebase-идентичностью.

Запись профиля выполняется отдельно от входа: отказ Firestore больше не превращает успешную Firebase-аутентификацию в ошибку входа. Firebase ID token обновляется, проверяется соответствие UID при смене аккаунта. Отключённая/удалённая учётная запись не получает доступ через старый кэш. Истечение тестовых правил Firestore 28.07.2026 было причиной ошибки опубликованной версии; владелец обновил правила и подтвердил вход. Это подтверждение относится к опубликованной версии, а не к новому AAB.

## Подписка и Render

Render обслуживает проверку Google Play, а не вход пользователей. API версии 2 принимает Firebase ID token и проверяет его через Firebase Admin SDK. Токен покупки связывается с Firebase UID; локальный флаг/поле Firestore не предоставляет Premium. Цена поступает из Google Play. Подтверждение покупки выполняет сервер после проверки конкретного чека; клиент не подтверждает повторно и не подтверждает ожидающий чек из-за другой активной подписки. Кэш проверенного доступа ограничен 24 часами и сроком подписки.

### Что сделать на Render

1. Обновить сервер файлами из `render-billing-update-1.3.1.zip` (или соответствующим проверенным коммитом). Архив не содержит секретов, базы и node_modules. Node.js 22, установка `npm ci`, запуск `node index.js`.
2. Подключить постоянный диск и установить `DB_PATH=/var/data/users.db`. Существующие данные SQLite предварительно резервировать, если они нужны. Firebase-пользователи хранятся в Firebase: переносить их в SQLite не требуется. Диск нужен для постоянного реестра покупок.
3. Сохранить существующие секреты. Проверить `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` либо `GOOGLE_APPLICATION_CREDENTIALS`, доступ служебного аккаунта к приложению/подпискам, включённый Android Publisher API. Приватные ключи в приложение и Git не добавлять. `google-services.json` не является ключом служебного аккаунта.
4. Развернуть сервер. `/billing/status` должен вернуть `billingApiVersion: 2`, `identityProvider: firebase`, `firebaseProjectId: agronomonline-68820`, `productId: agronom_premium_monthly`, `billingReady: true`. Последнее проверяет существующий активный месячный auto-renewing план. Без авторизации `/billing/entitlement` должен отвечать 401.
5. Проверить публичные `/privacy-policy`, `/terms-of-use`, `/account-deletion` и указанные в них контакты; актуализировать ссылки и декларацию данных в Play Console.

Сервер автоматически не опубликован. На последней проверке действующий Render возвращал 404 для `/billing/status`; наличие ключа само по себе новый обработчик не добавляет. До готовности сервера новые покупки заблокированы, бесплатные инструменты и Firebase-вход доступны.

## Проверка перед производственным выпуском

Локальные проверки: статический анализ, Flutter-тесты авторизации/инструментов/ограничений, серверные тесты с изолированной SQLite и имитацией Google API; npm audit без известных уязвимостей. Точное число и результаты проверки AAB — в `verification.json` рядом со сборкой.

Обязателен внутренний трек Google Play: обновление поверх 1.2.4 без удаления данных; вход существующим Google и email-аккаунтом с тем же UID/профилем; новая регистрация; покупка, восстановление старой подписки, отмена/истечение, смена аккаунта и работа без сети. Проверить реальные Play-подписанные сертификаты и права служебного аккаунта. Модульные тесты не заменяют эти операции. Телефон в текущем задании не переустанавливался.

Android AAB — цель этого выпуска. Web требует FIREBASE_WEB_APP_ID/FIREBASE_WEB_API_KEY при сборке; web/iOS/desktop здесь не проверялись. Приложение не опубликовано автоматически. Производственный выпуск до проверки сервера и реальных покупок не подтверждён.

Сборка выполняется вне OneDrive из сверяемого снимка исходников. В текущем процессе новые копии signing-файлов не создаются. Ранее созданные временные signing-файлы в старом staging остались после отклонённой автоматической очистки; не распространять staging.
